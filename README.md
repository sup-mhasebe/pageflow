# PageFlow

冊子制作の前段階で、**ページ構成の検討・完成PDFの確認・中綴じ面付の確認**をブラウザ上で行うための、小さな業務アプリです（v0.1）。

実際のデザイン調整や印刷データの制作は Canva などで行い、PageFlow は「冊子の設計とシミュレーション」を担当します。

- 公開URL：https://pageflow-dyu.pages.dev （Basic認証で保護されています）
- 社内AI研修「09 宿題」Level 2 の提出物です

## 主な機能

| 機能 | 内容 |
|---|---|
| 冊子作成 | 冊子名と総ページ数を指定して作成。表紙・表紙裏・目次・裏表紙裏・裏表紙を「標準構成」として自動生成（作成後は通常コンテンツと同様に移動・削除可能） |
| コンテンツ登録 | コンテンツ名と必要ページ数を登録・編集・削除 |
| D&Dによるページ配置 | コンテンツをページカードへドラッグして配置。複数ページは連続して確保。移動・配置解除にも対応 |
| PDF登録・割当 | コンテンツ単位で完成PDFを登録し、ページごとの素材（表示用画像）を生成。登録と冊子ページへの割当は別操作。差し替え・登録解除・簡易ゴミ箱に対応 |
| A3 → A4×2 分割 | A3横のPDFは分割前に全体と中央50%の分割線を確認し、左 → 右の順に2つのA4相当素材へ分割 |
| 冊子ビューア | 一覧表示／見開き表示、40〜200%ズーム、全体表示、ページ情報ON/OFF、赤い綴じ辺ガイド、前へ／次へ、左右スワイプ。スマートフォンでも見開き関係を維持し、画面幅に合わせて縮小表示 |
| 中綴じ面付シミュレーション | 総ページ数から面付を自動計算し、A3の各面を縦に1面ずつ表示 |
| `.pageflow` 書き出し／読み込み | ビューア専用データを1ファイルで書き出し、別の端末で読み込んでビューアを表示 |

## 対応仕様（v0.1）

- 冊子の種類：**中綴じ・左綴じ・A4縦**
- 総ページ数：**8ページ以上の4の倍数**（4ページでは標準構成が重なるため作成できません）
- 標準構成：表紙（P1）・表紙裏（P2）・目次（P3）・裏表紙裏（P(N-1)）・裏表紙（PN）。固定ページではなく、作成後に通常コンテンツと同様に移動・削除できます
- 登録できるPDF：**A4縦** と **A3横**（A4横・A3縦・その他のサイズは登録できません）
- 編集はPCを想定。ビューアはPC・スマートフォンで閲覧できます

### スマートフォンビューア

スマートフォンでも見開き関係を維持し、画面幅に合わせて縮小表示します。前へ／次へ、左右スワイプにも対応します。

```
P1：単独
P2 LEFT | P3 RIGHT
P4 LEFT | P5 RIGHT
...
最終偶数ページ：単独
```

### 面付画面の見方

面付画面の「面付データ 1ページ目、2ページ目…」は、Canva などで作成する**A3面付データ側のページ順**です。冊子のページ番号（P1、P2…）とは別のものです。

例：8ページの冊子

| 面付データ | 用紙・面 | 左 | 右 |
|---|---|---|---|
| 1ページ目 | 用紙1・外側 | P8 | P1 |
| 2ページ目 | 用紙1・内側 | P2 | P7 |
| 3ページ目 | 用紙2・外側 | P6 | P3 |
| 4ページ目 | 用紙2・内側 | P4 | P5 |

## データについて

- 編集データ（冊子・コンテンツ・登録したPDF・生成した画像）は、**使用しているブラウザの IndexedDB** に保存されます。サーバーには保存されません。
- PDFの解析・画像生成はすべて**ブラウザ内**で行います。**PDFや画像を外部サーバーへアップロードすることはありません。**
- 編集データは、ブラウザや端末を変えると共有されません。ブラウザのサイトデータを消去すると、編集データも消えます。
- `.pageflow` は**閲覧専用のデータ**です。表示用の画像と最小限の情報だけを含み、元のPDF・編集状態・ゴミ箱の内容等は含みません。
- 読み込んだ `.pageflow` は、その場で閲覧するだけで保存されません（編集データにも登録されません）。
- 冊子ごとの共有URLはありません。別の端末で見せたいときは `.pageflow` ファイルを渡します。

## 技術構成

研修 Level 2 の必須技術と、PageFlow 固有の技術です。

| 区分 | 技術 | PageFlow での使いどころ |
|---|---|---|
| Level 2 必須 | Vite | 開発サーバーとビルド |
| Level 2 必須 | JavaScript | フレームワークを使わない素の ES Modules |
| Level 2 必須 | Tailwind CSS | 画面全体のスタイル（スマートフォン幅にも対応） |
| Level 2 必須 | zod | 冊子名・総ページ数・コンテンツ入力の検証、保存データと `.pageflow` の `manifest.json` の検証 |
| Level 2 必須 | pnpm | 依存パッケージの管理 |
| Level 2 必須 | Git / GitHub | ソース管理 |
| Level 2 必須 | Cloudflare Pages | アプリ本体の公開 |
| 固有 | IndexedDB | 冊子・コンテンツ・PDF・生成画像の保存（外部DBは使いません） |
| 固有 | PDF.js（pdfjs-dist） | PDFの解析と描画 |
| 固有 | Canvas API | 表示用画像の生成、A3の中央分割 |
| 固有 | fflate | `.pageflow`（ZIP形式）の生成と展開 |
| 固有 | HTML Drag and Drop API / Pointer Events | ページ配置のドラッグ＆ドロップ、ビューアのスワイプ操作 |

アプリ独自のサーバーやデータベースサーバーはありません。ビルド結果は静的ファイルだけです。

## ローカル起動

必要なもの：Node.js（22.13 以上を推奨。開発・検証は 24.19 で実施）と pnpm

```bash
pnpm install
pnpm dev
```

表示されたURL（通常は http://localhost:5173/ ）をブラウザで開きます。

| コマンド | 内容 |
|---|---|
| `pnpm dev` | 開発サーバーを起動 |
| `pnpm build` | 公開用にビルド（出力先：`dist/`） |
| `pnpm preview` | ビルド結果をローカルで確認 |
| `pnpm test` | 単体テストを実行（Node 標準の `node:test`） |

## 使い方（基本の流れ）

1. ホームで［新しい冊子を作成］を押し、冊子名と総ページ数（8以上の4の倍数）を入力します。
2. 「構成」タブで、コンテンツ名と必要ページ数を登録します。
3. コンテンツをページカードへドラッグして配置します。
4. コンテンツにPDFを登録します（A3横は分割内容を確認してから登録します）。PDFを登録しただけでは冊子ページへ割り当てられません。［PDFを順番に割り当て］または素材の個別D&Dで割り当てます。
5. 「冊子プレビュー」タブで、見開きで確認します。「面付」タブで、中綴じの面付を確認します。
6. ［ビューア用データを書き出す］で `.pageflow` を作成し、別の端末のPageFlowで［ビューア用データを読み込む］から開きます。

### PDF登録と冊子ページへの割当

PDF登録と冊子ページへの割当は別操作です。PDFを登録しただけでは、冊子ページへ自動割当しません。

割当方法：

1. ［PDFを順番に割り当て］
2. PDF素材を個別にD&D

［PDFを順番に割り当て］は、未割当素材をPDF順に、対象コンテンツの未割当ページへ物理ページ順に割り当てます。既存の割当は上書きしません。

### PDF素材数とコンテンツのページ数

- PDFから生成される素材数が `requiredPages`（コンテンツの必要ページ数）より多くても登録できます。余剰素材は未割当のまま保持されます。
- 素材数が `requiredPages` より少なくても登録できます。
- A3横は中央50%で分割し、左 → 右の順に2つのA4相当素材として扱います。

### 削除・解除の違い

| 操作 | 結果 |
|---|---|
| 配置を解除 | ページへの配置だけを外します。コンテンツと登録済みPDFは残ります |
| PDF登録を解除 | PDFとの関連だけを外します。コンテンツと配置は残ります。元PDFはゴミ箱へ移すか完全削除するかを選びます |
| コンテンツを削除 | コンテンツと配置を削除します。PDFがある場合は、ゴミ箱へ移すか完全削除するかを選びます |
| 冊子を削除 | 冊子と登録PDFを含むすべてのデータを削除します（元に戻せません） |

## 公開（Cloudflare Pages）

| 項目 | 設定値 |
|---|---|
| フレームワーク | なし（Vite の静的ビルド） |
| ビルドコマンド | `pnpm build` |
| ビルド出力ディレクトリ | `dist` |
| 環境変数 | `NODE_VERSION`（例：`22`） |

### アクセス制限（Basic認証）

公開URLはBasic認証で保護されています。

- `functions/_middleware.js`（Cloudflare Pages Functions）がサイト全体にBasic認証をかけます
- 認証情報は環境変数 `BASIC_AUTH_USER` / `BASIC_AUTH_PASSWORD` で、Cloudflare Pages の Secret として管理します
- Secret が未設定の場合は、認証なしで公開されないよう 503 を返します（fail-closed）
- `/robots.txt` のみ認証の対象外です（`Disallow: /` で検索エンジンへの登録を拒否）
- 認証情報の実値は、リポジトリに保存しません

## AIをどう使ったか

PageFlow は、複数のAIツールと人間で役割を分担して開発しました。AIがすべてを自動で作ったものではありません。

| 担当 | 役割 |
|---|---|
| ChatGPT | 要件整理、仕様決定の支援、設計レビュー、テスト・受入方針の整理、Claude Code への実装依頼の整理 |
| Claude Code | 主な実装、ローカルでのテスト、Git作業 |
| 人間 | 仕様の最終判断、実機での確認、受入判定 |

仕様の判断と受入は人間が行い、各段階の結果を確認してから次へ進みました。

## 注意事項

- デモや提出では、**架空のデータだけ**を使用してください。実在の顧客名・案件名・個人情報を含むPDFは使わないでください。
- v0.1 では**最終印刷用PDFそのものは生成しません**。面付画面は、Canva などで印刷データを作成する際の**確認・シミュレーション用途**です。
- 冊子ごとの共有URL、ノンブル、0.5ページ、1ページへの複数コンテンツ配置、見開きの必須・推奨判定、ユーザー作成テンプレートは、v0.1 の対象外です。
- PDFに埋め込まれていない日本語フォントなどは、正しく表示されない場合があります（Canva などから出力した、フォントが埋め込まれたPDFを想定しています）。
